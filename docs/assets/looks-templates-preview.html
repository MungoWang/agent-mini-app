现在为什么拧巴

同一套视觉被讲了两遍，但两边都没把该讲的讲完。

Paradigms · 画廊

9 个完整 React 皮肤，约 2500 行 / 100KB，被 gen:skill 原样拷进 skill。

  • saas / ops / darkdata 都是 dashboard，课重复
  • 大量 rgba / hex / 强制暗色，违反 token 规则
  • SKILL.md 热路径根本不指向它们
  • 模型要么看不见，要么整页吞掉

Templates · 门面

8 个能力轴是对的（storage / http+llm / system / agent / install…）。

  • 看起来几乎都是 Header + Card 列表 + Primary button
  • 还没用上 layout presets（ListDetail 已落，其余 5 个在做）
  • 没有官方「把画廊风格融进去」的写法
  • 所以模型抄完仍是灰卡

两层，不要第三套样例

配色 × layout 的组合以 Look 为单位固化，不按笛卡尔积再复制成 template。

01 · TEMPLATE

能力门面

可运行的 mini-app。ctx.* 轴 × kit preset × 已经戴好的默认 Look。模型抄结构、命名、取消/进度、call 形状。产品文案中文。

02 · LOOK

风格配方

一份 JSON/YAML 规格 + 一张 PNG。字段：何时用 / 何时不用、推荐 palette、layout grammar、surface、density、motion、data-look 与 class recipe。不是应用。

03 · EXAMPLES

组件用例

ui-examples/src/components 不动。继续按 @exampleOf 喂 catalog。不承担风格课。

PRESET 解决滚动/分栏这类 agent 会写错的页面形状 · LOOK 解决半径/密度/玻璃/便当/等宽这些视觉语法

Lookbook · 9 个冻结组合

盖住颜色，线框必须能分开。岛是「上半海报、底下两条」；便当是「六列三行铺满」。每条左 light、右 dark。

官方融合方式

这是推荐实践，不是框架闸门。kit 不增 Look API；模型可以完全手写。我们只保证：门面自己已经用这些实践做好看，Look 规格 + PNG 在被问到风格时够抄。

推荐，不强制

颜色走 token / color-mix，页面形状走 preset，视觉语法抄规格里的 Tailwind 字面量。SKILL.md 已有的那条仍成立：库是便利，自由发挥是预期。Look 目录是参考，不是必须点名一个 id。

"classes": {
  "root": "h-full p-6 gap-3",
  "island": "rounded-3xl backdrop-blur-2xl bg-card/40 border-border/50",
  "widget": "rounded-3xl bg-card/35 p-5"
}

data-look 只是一种可选配方

规格可以展示「根节点挂一个 look id、下面用同一组 class」这种写法，方便换肤。它不是运行时协议，不进 globals.css，模型不用也可以。换风格 = 改 class / 结构，不动 call。

/* optional, not a platform attribute */
<div data-look="glass-island" className={classes.root}>
  <section className={classes.island}>…</section>
</div>

唯一要锁的是 catalog 自己不漂：Look JSON 是预览/PNG 的源；demo-host fixture 读它来截图。不扫门面源码、不要求 ui.tsx 含 signature class。硬约束仍只有现有的那些：无 hex、无出目录 import、preset 自己的滚动契约。

七座门面 · 七种运转

切的是 loop，不是 API 名。抄错一座，app 的运转方式就错。骨架另算。表单 / 编辑器 / 日历 / 聊天不是门面，是套件。

门面 运转 Preset 默认 Look 抄它，当用户要的是
0 骨架 minimal 跑通一轮 call AppShell — 连通性 / 空壳
1 今日台子 today 打开就看见我的一屏，点进去是一条记录 ListDetail + 岛 glass-island 先干哪个、我的东西
2 阶段看板 board 多条在二维状态里移动 无（Kanban + Sheet） aurora-bento 卡住了、在等谁、按阶段追
3 信息雷达 radar 我触发 → 等 → 读一篇（可取消） Dashboard / Wizard editorial-prose 拉源、做简报、长任务
4 表格台 sheets 文件进，格子上干活，哪里变了 TablePage desk-split xlsx / 对比 / 列统计 / 安装库
5 执行器 runner 模型自己走多步，UI 就是这条 run 手写 timeline terminal-log agent、多步、边跑边看
6 一键杂事 chores 按钮、已知脚本、这台机器、看输出。无模型 AppShell terminal-log 整理下载、备份、一个按钮
7 值班屏 watch 打开就自己在跳。没有「开始」 DashboardShell tape 活的状态、灯、切走后台要停

不占门面的 Look：saas-board 缺省专业；void / signage 点名才套。用户说「赛博值班」→ 抄 watch 的运转（tape），排字按 signage 改。不加第八座产品。 chores 必须是按钮；一做成 prompt 就和 runner 撞车。

skill 热路径不再拷 400 行 TSX。有视觉的模型先看 PNG；没有视觉的模型读字段。fixture 仍留在 demo-host，只为人类预览和截图，不进 skill。

PNG 合同

  • 画幅固定：1280×720，内容是 mini-app 面板，不是营销整站。
  • Chrome 可以画一条假地址栏，方便视觉模型认出「这是 UI 预览」。
  • 每个 Look 一张特征模式图；不强制再出一张反色对图（规格里写明 light/dark 都能用）。
  • 由 Playwright 截 demo-host lookbook 生成，check:skill 要求每个 id 都有 png。
  • 现有 semantic.tsx 不再当 Look：那是 theme 课，写进 styling.md 一行。

模型怎么读（省 token）

1

SKILL.md 表：按运转选门面。默认不打开 looks。

2

打开那一座。它已经戴好默认 Look，是可抄的产品，不是灰卡。

3

仅当用户点名风格：looks/index.md → PNG → 规格。

4

把 class / grammar 融进这座门面。不新开应用，不强制 Look id。

现在 paradigms 进 skill 约 100KB 且不在热路径。替换后：index 表 ~2KB + 被选中的一份规格 ~2KB + 一张图。demo-host 继续做真人画廊和截图源。
