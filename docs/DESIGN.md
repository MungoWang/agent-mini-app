# monkey-mini-app Design Specification

> **Product name:** monkey-mini-app  
> **Status:** Implementation-ready baseline  
> **Audience:** Engineers and coding agents (LLMs) implementing the system  
> **Inspired by:** OpenMini (hexagonal architecture, host-agnostic bridge, permissions, host-defined APIs) — adapted for AI-generated filesystem apps and multi-host deployment (Tauri / Web Server / dsh plugin).

This document is the single source of truth for **monkey-mini-app**. An implementer should be able to build a working system from this file alone without prior conversation context.

**npm scope:** `@monkey-mini-app/*`.

---

## 1. Goals and Non-Goals

### 1.1 Goals

1. **Local unified host** that loads many mini-apps from a well-known directory.
2. **AI agent generates mini-apps at runtime** as ordinary file trees (not published npm packages).
3. **Infrastructure** (host core, bridge, API client, themes) is installed as **npm packages**.
4. **Shared theme tokens** so the host can restyle all apps by changing CSS variables.
5. **Multi-host reuse:** same core runs under Tauri, a Web Server, or a dsh plugin via adapters.
6. **Bidirectional capability model:**
   - Mini-apps call host/runtime capabilities through a typed bridge.
   - Host shells call the runtime through a stable `RuntimePort` API.
7. **Predictable structure** for AI generation without blocking creativity on UI implementation.
8. **Self-contained per-app storage** as lightweight JSON files under each app directory (multiple files allowed).
9. **Per-app version history** (commit / revert / reset) for backup and recovery, via a swappable `HistoryPort` (default: isomorphic-git).

### 1.2 Non-Goals

- Replacing WeChat / Alipay mini-program ecosystems.
- Running untrusted third-party mini-apps from the public internet (default trust model is local agent–generated code).
- Forcing a single component library (e.g. only shadcn).
- Shipping package **source** inside the global runtime directory.
- Full OpenMini `.mpkg` + static CDN registry as the primary distribution path (optional later).
- Product-level multi-branch workflows or merge (history uses a single `main` branch; see §8b).

---

## 2. Trust Model

1. Mini-apps are **locally generated by an AI agent** (or developers) on the same machine.
2. They are treated as **semi-trusted**: must declare permissions; undeclared bridge APIs are rejected.
3. Write access to `apps/` and ability to run the agent are security boundaries — protect them like code execution.
4. Shared npm packages (`@monkey-mini-app/*`) are installed by the Desktop installer or package manager and are **more trusted** than individual mini-apps.
5. Do not assume isolation between mini-apps beyond separate mount instances and permission checks (stronger isolation is future work).

## 3. High-Level Architecture

```
┌──────────────────────────────────────────────────────────────┐
│  Host Shell (Tauri UI / Web admin / dsh commands)            │
│  consumes RuntimePort                                        │
└────────────────────────────┬─────────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────────┐
│  Host Adapter (Tauri | Node/Web | dsh)                       │
│  implements HostPort                                         │
└────────────────────────────┬─────────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────────┐
│  Runtime Core (host-agnostic)                                │
│  AppRegistry · Loader · ThemeService · BridgeHub · Caps      │
└────────────────────────────┬─────────────────────────────────┘
                             │ Bridge Protocol
┌────────────────────────────▼─────────────────────────────────┐
│  Mini Apps under apps/<appId>/  (AI-generated files)         │
│  uses @monkey-mini-app/api-client → bridge.call / host.invoke │
└──────────────────────────────────────────────────────────────┘

node_modules/@monkey-mini-app/*   ← infrastructure npm packages only
```

**Rule:** Runtime Core must not import Tauri, Express, or dsh SDKs. Only adapters may.

## 4. Runtime Root (Installed State)

The runtime root is the **global install / data directory** for monkey-mini-app. It is a **Node project used as an install root**, not a source monorepo.

### 4.0 Configurable paths

All global locations are **configurable**. Resolution order (highest wins):

1. **Constructor / CLI flags** passed into `createRuntime` or the host binary  
2. **Environment variables**  
3. **User config file** (optional machine-wide)  
4. **Built-in defaults**

| Purpose | Env var | Default |
|---------|---------|---------|
| Runtime root (apps, config, node_modules) | `MONKEY_MINI_APP_ROOT` | `~/.monkey-mini-app/runtime` |
| Shared folder (optional extra shared assets outside the Node project) | `MONKEY_MINI_APP_SHARED` | `~/.monkey-mini-app/shared` |
| User config file | `MONKEY_MINI_APP_CONFIG` | `~/.monkey-mini-app/config.json` |

Example user config (`~/.monkey-mini-app/config.json`):

```json
{
  "runtimeRoot": "~/Projects/monkey-runtime",
  "sharedRoot": "~/Projects/monkey-shared",
  "themeId": "dark"
}
```

Example `createRuntime` override:

```ts
await createRuntime({
  host: hostPort,
  runtimeRoot: "/custom/path/monkey-runtime",
  sharedRoot: "/custom/path/monkey-shared", // optional
  configPath: "config/host.json", // relative to runtimeRoot
});
```

- **`runtimeRoot`**: required; contains `package.json`, `node_modules`, `apps/`, `config/`.  
- **`sharedRoot`**: optional; host may put cross-project assets here (templates, agent skills, caches). Not required for core boot if everything lives under `runtimeRoot`.  
- Paths may use `~`; adapters expand to the home directory. Relative paths in `config/host.json` resolve against `runtimeRoot`.

### 4.1 Directory Layout

Default layout (after expanding defaults):

```text
~/.monkey-mini-app/
├── config.json                  # optional machine-wide path overrides
├── shared/                      # optional MONKEY_MINI_APP_SHARED
│   ├── skills/                  # optional agent skills / prompts
│   └── templates/               # optional app scaffolds
└── runtime/                     # MONKEY_MINI_APP_ROOT
    ├── package.json
    ├── pnpm-lock.yaml
    ├── node_modules/            # @monkey-mini-app/*
    ├── config/
    │   ├── host.json
    │   └── apps.json
    ├── apps/
    │   └── <appId>/
    │       ├── manifest.json
    │       ├── App.tsx
    │       ├── main.api.ts
    │       ├── components/
    │       ├── hooks/
    │       ├── utils/
    │       ├── styles/
    │       ├── types/
    │       └── storage/
    ├── data/
    │   └── cache/
    └── logs/
```

Hosts may set `runtimeRoot` to any absolute directory (e.g. Tauri app data dir, dsh plugin data dir) without using the default `~/.monkey-mini-app` tree.

### 4.2 Root `package.json`

```json
{
  "name": "monkey-mini-app-runtime",
  "private": true,
  "type": "module",
  "dependencies": {
    "@monkey-mini-app/runtime-core": "^1.0.0",
    "@monkey-mini-app/bridge-protocol": "^1.0.0",
    "@monkey-mini-app/api-client": "^1.0.0",
    "@monkey-mini-app/theme-light": "^1.0.0",
    "@monkey-mini-app/theme-dark": "^1.0.0"
  }
}
```

**Forbidden:** listing individual mini-apps as dependencies. Minis live only under `apps/`.

### 4.3 `config/host.json`

```json
{
  "appsRoot": "apps",
  "themeId": "light",
  "themePackagePrefix": "@monkey-mini-app/theme-",
  "sharedRoot": null,
  "storage": {
    "mode": "app-json",
    "defaultFile": "default.json",
    "directory": "storage"
  },
  "dev": {
    "transpileJsx": true
  }
}
```

- `sharedRoot`: absolute path, `~`-prefixed path, or `null` (use env / machine config / default).  
- `storage.mode`: always `app-json` for v1.  
- `storage.directory`: subdirectory inside `apps/<appId>/` (default `storage`).  
- `storage.defaultFile`: used when API callers omit `file` (default `default.json`).

Do not hard-code `runtimeRoot` inside `host.json` if the process already selected the root by env/flag; optional `runtimeRoot` in machine config is enough for discovery.

### 4.4 Optional `config/apps.json`

```json
{
  "apps": [
    {
      "id": "com.example.todo",
      "path": "apps/com.example.todo",
      "enabled": true
    }
  ]
}
```

If missing, the runtime discovers apps by scanning `apps/*/manifest.json`.

## 5. Package Boundaries (What Is an npm Package)

| Artifact | npm package? | Location at runtime |
|----------|--------------|---------------------|
| Runtime core | Yes `@monkey-mini-app/runtime-core` | `node_modules` |
| Bridge protocol types/codec | Yes `@monkey-mini-app/bridge-protocol` | `node_modules` |
| Mini-side API client | Yes `@monkey-mini-app/api-client` | `node_modules` |
| Theme packs | Yes `@monkey-mini-app/theme-<id>` | `node_modules` |
| Host adapters | Yes `@monkey-mini-app/adapter-tauri` etc. | `node_modules` or bundled into host binary |
| Mini-app | **No** | `apps/<appId>/` files written by AI |

Desktop installer only runs package installs for `@monkey-mini-app/*` (and peers like `react` if required by the shell).

## 6. Mini-App Conventions (AI-Facing)

### 6.1 Required Files

| File | Required | Purpose |
|------|----------|---------|
| `manifest.json` | Yes | Identity, entry, permissions |
| Entry module (`App.tsx` or path in manifest) | Yes | UI entry; default export React component |

### 6.2 Allowed Directories

- `components/` — app-local UI
- `hooks/` — app-local hooks
- `utils/` — app-local utilities
- `styles/` — app-local CSS (must use theme tokens for design values)
- `types/` — optional local types
- `storage/` — self-contained JSON store files (runtime-managed; see §8a)
- `main.api.ts` — recommended wrappers around bridge/host APIs

### 6.3 `manifest.json` Schema

```json
{
  "$schema": "https://example.local/schemas/mini-manifest.schema.json",
  "id": "com.example.todo",
  "name": "Todo",
  "version": "0.1.0",
  "entry": "App.tsx",
  "permissions": ["storage", "host:getUser"],
  "theme": {
    "followsHost": true
  }
}
```

**Field rules:**

- `id`: reverse-DNS, unique under `apps/`, directory name **must equal** `id`.
- `entry`: relative path to the module that default-exports a React component.
- `permissions`: list of capability names or patterns the app may call.
- `theme.followsHost`: if `true` (default), app does not load its own theme; host CSS variables apply.

### 6.4 Imports Allowed in Mini Source

1. Relative imports within the app directory.
2. `@monkey-mini-app/api-client` (and other explicitly documented `@monkey-mini-app/*` packages).
3. `react` / `react-dom` (provided as peer by host loader; do not bundle a second copy when mounting in-process).
4. Optional UI libraries (e.g. code generated in the style of shadcn) **vendored into the app tree or allowed by host policy** — not a second full design-system framework unless host allows it.

**Forbidden:**

- Implementing private auth/request/storage stacks that bypass the bridge.
- Hard-coded brand colors in CSS (hex/rgb for themeable surfaces) — use tokens (see §8).

### 6.5 `main.api.ts` (Recommended Pattern)

```ts
import { mini } from "@monkey-mini-app/api-client";

export async function getUser() {
  return mini.host.invoke("getUser", {});
}

export async function loadItems(key: string) {
  return mini.storage.get(key);
}
```

UI code prefers calling `main.api` helpers rather than scattering raw bridge calls (not enforced by runtime, enforced by AI skill/docs).

## 7. Ports and Adapters

### 7.1 `HostPort` (Runtime → Host Platform)

Implemented by each adapter. Runtime core depends only on this interface.

```ts
/** Platform services the runtime needs from the host environment. */
export interface HostPort {
  /** Absolute runtime root path (expanded). */
  getRuntimeRoot(): string;

  readFile(absOrRuntimeRelativePath: string): Promise<string | Uint8Array>;
  writeFile(absOrRuntimeRelativePath: string, data: string | Uint8Array): Promise<void>;
  listDir(absOrRuntimeRelativePath: string): Promise<string[]>;
  exists(absOrRuntimeRelativePath: string): Promise<boolean>;

  /**
   * Host-defined native/platform APIs (camera, notifications, OS dialogs, …).
   * Name is without "host:" prefix; bridge maps host:X → invoke("X").
   */
  invoke(name: string, payload: unknown): Promise<unknown>;

  /**
   * Optional: if omitted, runtime implements JSON file storage under
   * apps/<appId>/storage/ using HostPort readFile/writeFile/listDir only.
   * Prefer omitting this so storage stays self-contained in the app tree.
   */
  storage?: {
    /** @deprecated Prefer app-directory JSON storage (§8a). */
    get(namespace: string, key: string): Promise<string | null>;
    set(namespace: string, key: string, value: string): Promise<void>;
    delete(namespace: string, key: string): Promise<void>;
  };

  /** Optional: system preference for color scheme. */
  getSystemColorScheme?(): Promise<"light" | "dark" | "no-preference">;

  log?(level: "debug" | "info" | "warn" | "error", message: string, meta?: unknown): void;
}
```

**Adapter notes:**

| Host | Implementation sketch |
|------|------------------------|
| Tauri | `fs` plugin, path resolver under app data; `invoke` → Tauri commands |
| Web Server (Node) | `node:fs/promises`; `invoke` → server-side service modules |
| dsh plugin | Map to plugin data dir + plugin SDK APIs |

### 7.2 `RuntimePort` (Host Shell → Runtime)

Exposed by runtime core so shells can manage apps without knowing internals.

```ts
export type AppSummary = {
  id: string;
  name: string;
  version: string;
  enabled: boolean;
};

export type MountTarget =
  | { type: "element"; element: unknown }      // in-process DOM/React root
  | { type: "webview"; id: string }           // Tauri webview label / handle
  | { type: "iframe"; iframe: unknown }
  | { type: "headless" };                     // load without UI (tests)

export interface RuntimePort {
  listApps(): Promise<AppSummary[]>;
  getApp(id: string): Promise<AppSummary & { permissions: string[] } | null>;

  mount(id: string, target: MountTarget): Promise<void>;
  unmount(id: string): Promise<void>;

  listThemes(): Promise<{ id: string; label: string }[]>;
  getTheme(): Promise<string>;
  setTheme(themeId: string): Promise<void>;

  /** AI agent or tooling writes a full app tree, then registers it. */
  registerAppFromFiles(
    appId: string,
    files: Record<string, string>
  ): Promise<void>;

  removeApp(appId: string): Promise<void>;

  listCapabilities(): Promise<CapabilityDescriptor[]>;

  // App history (§8b) — optional at type level but required for agent workflows
  historyCommit?(appId: string, message: string): Promise<{ commitId: string }>;
  historyList?(appId: string, opts?: { limit?: number }): Promise<CommitTree>; // see §8b
  historyRevert?(appId: string, commitId: string, opts?: { message?: string }): Promise<{ commitId: string }>;
  historyResetTo?(appId: string, commitId: string, opts?: { createBackupRef?: boolean }): Promise<{ backupRef?: string }>;
}
```

Prefer wiring these as required methods once `@monkey-mini-app/app-history` is integrated (see §8b.9).

### 7.3 Creating the Runtime

```ts
import { createRuntime } from "@monkey-mini-app/runtime-core";

const runtime = await createRuntime({
  host: hostPortImplementation,
  configPath: "config/host.json", // relative to runtime root
});

// Shell uses runtime as RuntimePort
await runtime.setTheme("dark");
await runtime.mount("com.example.todo", { type: "element", element: rootEl });
```

## 8. Theme System

### 8.1 Responsibilities

| Layer | Responsibility | Forced on AI? |
|-------|----------------|---------------|
| Host base CSS (reset, default typography) | Soft global look; host may rebase | **No** |
| **Theme tokens (CSS variables)** | Colors, radii, spacing, fonts as variables | **Yes** — styles must reference tokens for themeable values |

The host controls unified theming by rewriting CSS variables on a root node. All mounted mini-apps inherit them.

### 8.2 Theme Packages

Each theme is an npm package, e.g. `@monkey-mini-app/theme-light`:

```text
node_modules/@monkey-mini-app/theme-light/
├── package.json
├── tokens.json
└── index.js          # export function getTokens(): Record<string, string>
                      # export const id = "light"
                      # export const label = "Light"
```

Example `tokens.json`:

```json
{
  "color-background": "#ffffff",
  "color-foreground": "#0a0a0a",
  "color-primary": "#2563eb",
  "color-primary-foreground": "#ffffff",
  "color-muted": "#f4f4f5",
  "color-muted-foreground": "#71717a",
  "color-border": "#e4e4e7",
  "color-destructive": "#dc2626",
  "radius-sm": "4px",
  "radius-md": "8px",
  "radius-lg": "12px",
  "space-1": "4px",
  "space-2": "8px",
  "space-3": "12px",
  "space-4": "16px",
  "font-sans": "ui-sans-serif, system-ui, sans-serif",
  "font-mono": "ui-monospace, monospace"
}
```

**CSS variable mapping:** key `color-background` → `--color-background` (prefix `--` + key as-is).

### 8.3 ThemeService Behavior

1. On startup, read `themeId` from `config/host.json`.
2. Resolve package `@monkey-mini-app/theme-${themeId}` (or configured prefix).
3. Call `getTokens()`, set properties on `document.documentElement` (or host-provided root).
4. On `setTheme(id)`, repeat and optionally persist `themeId` to `host.json` via `HostPort.writeFile`.
5. Optionally react to `getSystemColorScheme` if config enables auto theme.

### 8.4 Mini CSS Rules (for generators and linters)

**Allowed:**

```css
.card {
  background: var(--color-background);
  color: var(--color-foreground);
  border: 1px solid var(--color-border);
  border-radius: var(--radius-md);
  padding: var(--space-4);
}
```

**Disallowed** for themeable surfaces:

```css
.card {
  background: #ffffff; /* hard-coded */
  color: rgb(10, 10, 10);
}
```

Exceptions (document in comment or manifest later): charts, gradients, third-party embeds.

If Tailwind is used, host Tailwind config maps colors to CSS variables so utilities like `bg-background` resolve to `var(--color-background)`.

### 8.5 UI Libraries

- Host may ship optional primitives; **not mandatory**.
- AI may use shadcn-style components or custom components.
- Creativity is allowed; **token usage for themeable values is the hard constraint**.

## 8a. App Storage (Self-Contained JSON)

### 8a.1 Goals

1. **Self-containment:** all durable app data lives under `apps/<appId>/`, so copying or deleting the app directory moves or removes its data.
2. **Lightweight:** plain JSON files, no embedded database required for v1.
3. **Multi-file:** apps may split data across multiple JSON files (e.g. `default.json`, `settings.json`, `cache.json`).

### 8a.2 Layout

```text
apps/<appId>/
└── storage/
    ├── default.json       # default store (created on first write if missing)
    ├── settings.json      # optional extra store
    └── <name>.json        # any additional store file
```

- Directory name configurable via `config/host.json` → `storage.directory` (default `storage`).
- Only files ending in `.json` are valid store files.
- Runtime creates `storage/` on first successful write if it does not exist.

### 8a.3 File Format

Each store file is a single JSON **object** (map of string keys to JSON values):

```json
{
  "greeting": "hello",
  "count": 3,
  "items": [{ "id": "1", "title": "Task" }]
}
```

- Top-level must be an object, not an array or primitive.
- Values may be any JSON-serializable data.
- Missing file is treated as `{}`.
- Invalid JSON on read → runtime returns `HOST_ERROR` or `INTERNAL` and does not partially apply writes.

### 8a.4 Path Safety

When resolving `file` parameter from bridge calls:

1. Allow only a base name or a single path segment: `default`, `default.json`, `settings.json`.
2. If no `.json` suffix, append `.json`.
3. Reject `..`, `/`, `\`, empty string, and any path that would escape `apps/<appId>/storage/`.
4. Final path must equal `join(appsRoot, appId, storageDir, basename)`.

### 8a.5 Built-in Storage APIs

Permission for all: `storage`.

| API | Payload | Result |
|-----|---------|--------|
| `storage.get` | `{ key: string, file?: string }` | `{ value: unknown \| null }` |
| `storage.set` | `{ key: string, value: unknown, file?: string }` | `{ ok: true }` |
| `storage.delete` | `{ key: string, file?: string }` | `{ ok: true }` |
| `storage.keys` | `{ file?: string }` | `{ keys: string[] }` |
| `storage.clear` | `{ file?: string }` | `{ ok: true }` |
| `storage.listFiles` | `{}` | `{ files: string[] }` |

- `file` omitted → use `storage.defaultFile` (e.g. `default.json`).
- `storage.get`: missing key → `{ value: null }`.
- `storage.set` / `delete` / `clear`: read-modify-write the whole JSON object (v1). Implement atomic write via temp file + rename when the host filesystem allows.
- `storage.listFiles`: list `*.json` basenames under the app `storage/` directory (empty array if directory missing).

### 8a.6 Implementation Notes (Runtime Core)

Prefer implementing storage **inside runtime-core** using `HostPort.readFile` / `writeFile` / `listDir` / `exists`, **not** via optional `HostPort.storage`. That keeps behavior identical across Tauri / Node / dsh.

Pseudocode for `storage.set`:

```
path = safeResolveStoreFile(appId, file?)
obj = exists(path) ? JSON.parse(readFile(path)) : {}
obj[key] = value
writeFileAtomic(path, JSON.stringify(obj, null, 2))
```

### 8a.7 Concurrency (v1)

- No cross-process locking required for v1.
- Single runtime process: serialize storage operations per `appId+file` with an in-memory queue to avoid interleaved read-modify-write corruption.
- Document that multiple host processes on the same runtime root are unsupported for v1 unless external locking is added later.

### 8a.8 What Does *Not* Belong in `storage/`

- Theme files, manifests, source code.
- Host-global secrets (use host capabilities).
- Large blobs (images/videos): optional future API; v1 JSON only.

### 8a.9 AI Guidance

- Declare `"storage"` in `manifest.permissions` if any storage API is used.
- Split concerns across files when useful (`settings.json` vs `default.json`), still under `storage/`.
- Do not invent parallel `data/` folders for the same purpose; use `storage/*.json` via the bridge.

## 8b. App History (Version Control)

### 8b.1 Goals

1. Per mini-app **backup and recovery** of code/files (not a collaboration VCS product).
2. **Lightweight commits** via content-addressed storage so full history retention is acceptable (no prune/GC required in v1).
3. **Single-branch product strategy** (`main` only): no user-facing create-branch / list-branches / merge.
4. After **reset**, abandoned tips remain recoverable; **`listCommits` returns a tree** (nodes + `parentIds`), including backup tips.
5. Implementation behind **`HistoryPort`** so the default (isomorphic-git) can be replaced later.

### 8b.2 Non-Goals (History)

- Multi-branch development workflows or merge.
- Remote push/pull.
- Deleting commits or automatic prune.
- Versioning `storage/` by default (user data stays separate from code history).

### 8b.3 Mental Model (AI-Oriented, Git-Aligned)

| Concept | Meaning |
|---------|---------|
| **Commit** | Immutable node: `id`, `parentIds`, `message`, `time`, file tree |
| **main** | The only product branch; HEAD normally attached here |
| **Working tree** | Files under `apps/<appId>/` except `.git` and ignored paths |
| **backup/\*** | Protective refs created on `resetTo`; not a user branch API |

**Two different “undo” tools:**

| API | Effect on the graph | When to use |
|-----|---------------------|-------------|
| **`revert(commitId)`** | New commit on top of **current HEAD** that undoes that commit’s diff. History **moves forward**. Parent of the new commit is HEAD, **not** the reverted commit. | Fix a bad commit without moving `main` backward |
| **`resetTo(commitId)`** | Move **`main`** to `commitId` and check out that tree. Previous HEAD is stored as `backup/<iso-timestamp>`. Commits are **not deleted**. | Go back to an older state and continue editing from there |

**`revert` is not a fork from the target commit.**  
**`resetTo` is the way to get “continue from that old commit” under single-branch policy.**

### 8b.4 Layout (per app)

```text
apps/<appId>/
├── … working tree …
├── storage/                 # ignored by history (default)
└── .git/                    # owned by git adapter (or equivalent under other adapters)
```

Default ignore (adapter writes on `init`):

```gitignore
storage/
.DS_Store
node_modules/
```

### 8b.5 Package Split (Adapter Pattern)

| Package | Role |
|---------|------|
| `@monkey-mini-app/app-history` | `HistoryPort` types + factory that accepts an adapter |
| `@monkey-mini-app/app-history-git` | Default adapter: **isomorphic-git** |

Runtime core depends only on `HistoryPort`. It must not import `isomorphic-git` directly.

```ts
// Assembly (host bootstrap)
import { createGitHistoryAdapter } from "@monkey-mini-app/app-history-git";
import { createHistory } from "@monkey-mini-app/app-history";

const history = createHistory(createGitHistoryAdapter({ fs }));
```

Future adapters (e.g. Arc) implement the same `HistoryPort`; swapping adapters does not change Runtime/AI APIs. Existing on-disk repos are not automatically migrated.

### 8b.6 `HistoryPort` Interface

```ts
export type CommitNode = {
  id: string;
  parentIds: string[];
  message: string;
  time: string; // ISO-8601
};

/** Tree-shaped history for UI and agents (not a flat log-only API). */
export type CommitTree = {
  /** Current main / HEAD commit id */
  head: string;
  /** Nodes reachable from head and from backup/* refs (within limit) */
  nodes: CommitNode[];
  /** Optional: named tips for rendering (main + backups) */
  tips?: { name: string; commitId: string }[];
};

export type HistoryPort = {
  init(appDir: string): Promise<void>;

  commit(
    appDir: string,
    message: string,
    opts?: { author?: { name: string; email: string } }
  ): Promise<{ commitId: string }>;

  /**
   * Return history as a tree: nodes with parentIds.
   * Include commits reachable from main/HEAD and from backup/* refs.
   */
  listCommits(
    appDir: string,
    opts?: { limit?: number }
  ): Promise<CommitTree>;

  /**
   * Create a new commit that undoes the changes introduced by `commitId`.
   * Parent = current HEAD. On conflict → REVERT_CONFLICT, no partial write.
   */
  revert(
    appDir: string,
    commitId: string,
    opts?: { message?: string }
  ): Promise<{ commitId: string }>;

  /**
   * Point main at commitId and hard-checkout the working tree.
   * Default: create refs/backup/<iso> → previous HEAD (createBackupRef: true).
   * Does not delete any commits.
   */
  resetTo(
    appDir: string,
    commitId: string,
    opts?: { createBackupRef?: boolean }
  ): Promise<{ backupRef?: string }>;
};
```

**Error codes (stable):**

| Code | Meaning |
|------|---------|
| `NOT_INITIALIZED` | `init` not called / no repo |
| `NOT_FOUND` | Unknown commit id |
| `DIRTY_WORKTREE` | Uncommitted changes block an operation (if enforced) |
| `REVERT_CONFLICT` | Inverse patch could not be applied cleanly |
| `INTERNAL` | Adapter/runtime failure |

### 8b.7 Operation Semantics

#### `init`

- Create repo if missing; ensure branch `main`.
- Write default ignore (including `storage/`).
- Idempotent if already initialized.

#### `commit`

- Stage allowed paths (respect ignore).
- Create commit with single parent = current HEAD (or root if first).
- Fast-forward `main`.
- Default author may be `mini-agent <agent@local>` if not provided.

#### `listCommits` → `CommitTree`

1. Resolve `head` = `main` / HEAD.
2. Walk parents from `head` up to `limit` nodes.
3. Resolve all `refs/backup/*` (and equivalent); walk those tips into the same node set (dedupe by id).
4. Return `nodes` with accurate `parentIds`, plus optional `tips` for `main` and each backup.

After `resetTo`, the graph **must** show a fork when a backup tip still points at the abandoned line—so agents can recover without a branch UI.

#### `revert`

- Equivalent to `git revert <commitId>` (single commit, v1).
- New commit on current `main`; message default e.g. `revert: <id>`.
- Does **not** move `main` backward; does **not** mean “fork from that commit”.

#### `resetTo`

1. If `createBackupRef !== false`, create `refs/backup/<iso-timestamp>` → current HEAD.
2. Move `main` to `commitId`.
3. Check out working tree to match that commit (respect ignore: do not delete ignored paths such as `storage/` unless adapter documents otherwise; **preferred: leave `storage/` untouched**).
4. Return `{ backupRef }` when created.

Subsequent `commit` grows a new line from the reset point; old line remains via backup tip and appears in `listCommits` tree.

### 8b.8 Graph Examples

**After linear commits:**

```text
A → B → C → D → E (main/HEAD)
```

**After `resetTo(C)`:**

```text
A → B → C (main/HEAD)
         ↘
          D → E (backup/2026-…)
```

**After further `commit`:**

```text
A → B → C → F → G (main/HEAD)
         ↘
          D → E (backup/…)
```

**After `revert(C)` while HEAD was E (no reset):**

```text
A → B → C → D → E → R (main/HEAD)
```

`R` undoes `C`’s changes; parent of `R` is `E`.

### 8b.9 RuntimePort Integration

Expose thin wrappers (resolve `appId` → `appDir`):

```ts
// On RuntimePort (additions)
historyCommit(appId: string, message: string): Promise<{ commitId: string }>;
historyList(appId: string, opts?: { limit?: number }): Promise<CommitTree>;
historyRevert(appId: string, commitId: string, opts?: { message?: string }): Promise<{ commitId: string }>;
historyResetTo(appId: string, commitId: string, opts?: { createBackupRef?: boolean }): Promise<{ backupRef?: string }>;
```

Call `history.init(appDir)` when registering a new app or on first history use.

### 8b.10 isomorphic-git Adapter Notes

| HistoryPort | isomorphic-git (indicative) |
|-------------|----------------------------|
| `init` | `git.init` + default branch `main` + write `.gitignore` |
| `commit` | `git.add` (status matrix) + `git.commit` |
| `listCommits` | `git.log` from `main` + resolve `refs/backup/*` + merge node sets |
| `revert` | Build inverse tree / use available helpers; commit result; on failure `REVERT_CONFLICT` |
| `resetTo` | Write backup ref + move `main` + `git.checkout` |

- One repo per `apps/<appId>/` (`dir` = app directory, `gitdir` = `dir/.git`).
- No remotes required for v1.
- Full retention: do not run aggressive gc that drops backup-reachable objects.

### 8b.11 AI Agent Rules (History)

```text
MUST:
- Use only: commit, listCommits (tree), revert, resetTo
- After risky edits, prefer commit before experiments
- To undo a commit but keep main moving forward → revert
- To return to an old state and continue editing → resetTo
- Expect listCommits.nodes[].parentIds for tree rendering; use tips/backup to recover

MUST NOT:
- Create feature branches or merge
- Expect storage/ to be versioned
- Assume revert forks from the target commit (it does not)
- Delete backup refs or force-drop commits
```

### 8b.12 Security / Safety

1. Path: history only under the given `appDir`; no escape.
2. `resetTo` / checkout must not wipe `storage/` (ignored paths preserved).
3. Default backup ref on reset reduces damage from mistaken reset.
4. History APIs are host/runtime capabilities—not exposed as unrestricted mini-app bridge calls unless a future permission model allows a narrow subset.

## 9. Bridge Protocol

Design intent matches OpenMini: **host-framework-independent** JSON messages over an opaque transport.

### 9.1 Transport

Anything that can pass strings both ways:

- In-process function calls (same JS realm).
- `postMessage` (iframe / webview).
- Tauri event / channel.
- WebSocket (remote shell).

```ts
interface Transport {
  send(message: string): void;
  onMessage(handler: (message: string) => void): () => void; // returns unsubscribe
}
```

### 9.2 Envelope

Every message is one JSON object with `v` (protocol version, currently `1`) and `type`.

**Call (mini → host/runtime):**

```json
{
  "v": 1,
  "type": "bridge.call",
  "id": "c-42",
  "api": "storage.get",
  "payload": { "key": "items" }
}
```

**Result (host/runtime → mini):**

```json
{
  "v": 1,
  "type": "bridge.result",
  "id": "c-42",
  "ok": true,
  "result": { "value": "[]" }
}
```

**Error result:**

```json
{
  "v": 1,
  "type": "bridge.result",
  "id": "c-42",
  "ok": false,
  "error": {
    "code": "PERMISSION_DENIED",
    "message": "storage permission not declared"
  }
}
```

**Event (host/runtime → mini, fire-and-forget):**

```json
{
  "v": 1,
  "type": "host.event",
  "event": "theme.change",
  "payload": { "themeId": "dark" }
}
```

### 9.3 Correlation Rules

- `id` must be unique among in-flight calls from the caller.
- Exactly one `bridge.result` per `bridge.call`.
- Unknown `type` or fields: ignore for forward compatibility (do not crash).

### 9.4 Error Codes (closed set for v1)

| Code | Meaning |
|------|---------|
| `PERMISSION_DENIED` | Missing manifest permission |
| `NOT_FOUND` | Unknown API name |
| `INVALID_PAYLOAD` | Schema validation failed |
| `TIMEOUT` | Host did not respond in time |
| `HOST_ERROR` | HostPort.invoke threw |
| `INTERNAL` | Runtime bug |

### 9.5 Built-in APIs (runtime-provided)

| API name | Permission | Payload | Result |
|----------|------------|---------|--------|
| `storage.get` | `storage` | `{ key: string, file?: string }` | `{ value: unknown \| null }` |
| `storage.set` | `storage` | `{ key: string, value: unknown, file?: string }` | `{ ok: true }` |
| `storage.delete` | `storage` | `{ key: string, file?: string }` | `{ ok: true }` |
| `storage.keys` | `storage` | `{ file?: string }` | `{ keys: string[] }` |
| `storage.clear` | `storage` | `{ file?: string }` | `{ ok: true }` |
| `storage.listFiles` | `storage` | `{}` | `{ files: string[] }` |
| `theme.get` | none or `theme` | `{}` | `{ themeId: string }` |
| `ui.toast` | `ui` | `{ message: string }` | `{ ok: true }` |

Full storage semantics: **§8a**. Data is stored under `apps/<appId>/storage/*.json` (self-contained). Isolation between apps is by **directory**, not by a global key namespace.

Namespace for host-defined APIs: `host.<name>` in the `api` field maps to `HostPort.invoke(name, payload)`.

Permission entry: `host:<name>` or wildcard policy defined by runtime config (default: exact `host:<name>` required).

### 9.6 Permission Check Algorithm

```
on bridge.call(api, appId):
  manifest = loadManifest(appId)
  required = permissionFor(api)  // e.g. storage.get → "storage"; host.foo → "host:foo"
  if required and required not in manifest.permissions:
    return error PERMISSION_DENIED
  dispatch(api, payload)
```

### 9.7 Mini Client (`@monkey-mini-app/api-client`)

```ts
import { createMiniClient } from "@monkey-mini-app/api-client";

// Injected by loader when the app mounts
export const mini = createMiniClient(transport);

await mini.storage.get("items");
await mini.storage.set("items", [], { file: "default.json" });
await mini.storage.get("theme", { file: "settings.json" });
await mini.host.invoke("getUser", {});
mini.on("theme.change", (payload) => { /* ... */ });
```

`@monkey-mini-app/api-client` helpers should accept optional `file` for multi-file stores (default file when omitted).

Implementation detail: serialize calls, track pending Map\<id, {resolve,reject}\>, decode results.

## 10. Capability Registry

```ts
export type CapabilityDescriptor = {
  name: string;                    // "storage.get" | "host.scanQr"
  source: "runtime" | "host";
  permission?: string;
  inputSchema: Record<string, unknown>;   // JSON Schema
  outputSchema?: Record<string, unknown>;
  description?: string;
};
```

- Runtime registers built-in capabilities at startup.
- Adapter registers host capabilities when constructing `HostPort` / during `createRuntime`.
- `RuntimePort.listCapabilities()` returns the merged list (for shells and AI tooling).

AI generation should only call APIs present in this list (documented in the agent skill).

## 11. AppRegistry and Loader

### 11.1 Discovery

1. If `config/apps.json` exists, use enabled entries.
2. Else scan `apps/*/manifest.json`, validate `id === directory name`.

### 11.2 `registerAppFromFiles(appId, files)`

1. Validate `appId` format.
2. Write each path under `apps/<appId>/` (reject path escape `..`).
3. Validate `manifest.json` against schema.
4. Refresh registry cache.
5. Do **not** run `pnpm add`.

### 11.3 Mount Pipeline (in-process React example)

1. Resolve entry module path.
2. Ensure theme variables applied.
3. Create bridge transport bound to `appId`.
4. Provide `mini` global/injection for the module graph (loader-specific).
5. Import entry (dev: JSX transform / Vite middleware; prod: prebuilt `dist` if present).
6. Render default export into `MountTarget`.
7. On unmount: tear down React root, unsubscribe transport, revoke permissions context.

### 11.4 WebView / iframe Mount

1. Serve or inject an HTML shell that loads the app bundle + bridge client.
2. Wire `postMessage` transport to BridgeHub with `appId`.
3. Parent page already has theme variables on root; child documents may need variable injection into child `documentElement` (adapter responsibility).

## 12. Multi-Host Deployment

### 12.1 Tauri

- Runtime root: app data dir (e.g. resolve `~/.monkey-mini-app/runtime` or platform-specific).
- Adapter implements `HostPort` with Tauri fs/store/commands.
- UI shell in WebView calls `RuntimePort` via Tauri invoke or shared JS if core runs in webview.
- Optional: core runs in Rust sidecar Node; shell talks over IPC.

### 12.2 Web Server

- Node process owns `createRuntime(nodeHostPort)`.
- Expose HTTP/JSON-RPC or WebSocket API mapping to `RuntimePort`.
- Browser shell + mini mount (iframe or same-origin SPA regions).

### 12.3 dsh Plugin

- On plugin init: `createRuntime(dshHostPort)`.
- Commands map to `listApps` / `mount` / `setTheme` / `registerAppFromFiles`.
- Data directory = plugin-provided path mapped as runtime root.

**Same** `@monkey-mini-app/runtime-core`, **same** `apps/` layout, **same** bridge protocol.

## 16. Security Checklist for Implementers

1. Reject `..` in `registerAppFromFiles` paths.
2. Resolve storage files only under `apps/<appId>/storage/`; reject path escape in `file` parameter (§8a.4).
3. Enforce permissions on every `bridge.call`.
4. Validate host invoke payloads with JSON Schema when descriptor provides `inputSchema`.
5. Do not execute arbitrary shell from mini bridge APIs unless explicitly designed host capability with strong warnings.
6. Treat runtime root permissions as sensitive (agent write + package install).
7. Prefer atomic write (temp + rename) for storage JSON updates.
